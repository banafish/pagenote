## 一、背景与核心判断

### 现状盘点

| 维度 | 现状 | 位置 |
|---|---|---|
| 一级入口 | 时光 / 日历 / 统计 / 设置，共 4 个 | `lib/app.dart:64` |
| 入口容器 | 窄屏 `NavigationBar`，≥700dp 切 `NavigationRail` | `lib/widgets/adaptive_scaffold.dart:40` |

| 素材包导入 | 系统分享 / 打开文件 → 预览页 → 回跳对应管理页 | `lib/main.dart:232`、`:241`、`:249` |
| 素材包导出 | 管理页右上角进多选态，AppBar 整体替换 | `template_manager_page.dart:479`、`sticker_manager_page.dart:542` |

### 判断一：设置页正在变成功能抽屉

设置页的语义是「配置应用」，而「逛自己的模板与贴纸收藏」是内容消费行为，两者同列是信息架构错配。REQ-21 落地后这个错配被放大了：素材包从系统分享导入会自动回跳管理页（`main.dart:241`、`:249`），但用户此后想再找回这批素材，唯一路径是「设置 →写作 →我的素材」——**进来是一条外部深链，回去是一条埋了两层的内部路径，进出不对称**。

`docs/素材与模板管理需求.md` 为素材与模板单独立了一份需求文档、9 条需求、3 条非功能约束，它在产品分量上已是第二条核心循环，在导航分量上却等同于「字号调节」。

### 判断二：日历与统计是同一类面，但频次差一个数量级

两者都是「回看已写内容」，都以月为轴，心智上属于同一动作。但使用频次不同量级：

| | 日历 | 统计 |
|---|---|---|
| 动作性质 | 检索（找某天写了什么）| 阅读（看累计与趋势）|
| 典型频次 | 每次想翻旧内容都会用 | 周 / 月级别，被动浏览 |
| 数据尺度 | 月内 | 全局 + 近 7/30 天 |

让两者各占一个一级入口，等于用同等导航权重承载相差一个数量级的频次。合并是合理的——但**必须让高频的那个不付代价**：日历作为默认子页签，统计付出多一次点击。

顺带解决一个既有问题：月报现在从首页引导卡（`home_page.dart:170`）与统计页（`stats_page.dart:170`）两处进入，归属含混；合并后它在「回顾」内有了明确的家。

### 判断三：一级入口维持 4 个，不扩到 5

`NavigationBar` 支持 3～5 个目的地，扩到 5 在技术上可行。但本应用底栏之上还压着 FAB（`lib/app.dart:92`），且标签为二字中文，5 项会同时挤压标签可读性与 FAB 的安全边距。因此本次改造是**一进一出的置换**，不是扩容：

```
现状：  时光      日历      统计      设置
改后：  时光      素材      回顾      设置
                模板/贴纸  日历/统计  
```

改后节奏为「写（FAB）→ 存 → 看 → 设」，四个入口各自承载一类动作，语义不重叠。

## 二、P0 需求：一级入口置换

### REQ-23 素材库一级入口

- 参考产品：Procreate「画笔库」独立入口、GoodNotes 模板标签页、Telegram 贴纸管理
- 需求描述：把「手账模板」与「我的素材」从设置页提为一级入口，合并为一个「素材」目的地，内部分「模板 / 贴纸」两个子页签。二者交互模型本就相同（宫格 + 长按多选 + 导出为素材包），拆在设置里两行既重复又难找。

**验收标准**
1. 底部导航新增「素材」一级入口，图标与写作、统计族有足够区分度（建议 `Icons.palette_outlined` / `Icons.palette`）
2. 入口内为两个子页签，**默认落在「模板」**——内置模板保证首屏永不为空，新用户不会看到一个空白的一级入口
3. 子页签切换保留各自的滚动位置、排序方式（REQ-18.4）与网格状态；离开该一级入口再回来时恢复上次所在的子页签
4. 多选导出流程与现状一致：进入多选态后顶栏替换为「已选 N 项 + 全选 + 导出为素材包」。多选态下**隐藏子页签栏**，避免用户误以为可以跨页签混选
5. **`TemplateManagerPage` 与 `StickerManagerPage` 必须保留独立可 push 的整页形态**——编辑器贴纸面板（`canvas_tool_sheets.dart:809`）与素材包导入回跳（`main.dart:241`、`:249`）仍以整页方式打开它们，不得因改为子页签而失效
6. 素材包导入后的高亮定位（`highlightIds` / `highlightStickerIds`）在「一级入口子页签」与「独立整页」两种形态下表现一致
7. 宽屏（`NavigationRail`，≥700dp）下结构一致，且子页签不得与侧栏形成双层导航的视觉重复

**技术要点**：两个管理页当前均为完整 `Scaffold` + 自带 `AppBar`，且多选态是整体替换 AppBar（`template_manager_page.dart:437`、`sticker_manager_page.dart:506`）。直接塞进 `TabBarView` 会出现双层 AppBar。需先把两页拆为「纯 body widget」+「顶栏配置」两部分，由宿主页统一渲染顶栏；多选状态（`_selecting` / `_selectedIds`）与导出回调随之上提到宿主，或由各自的 controller 对外暴露。拆分完成后，独立整页形态即「宿主壳 + 单个 body」的薄封装，两种形态共用一套实现，不做双份维护。**这是本次改造的主要工作量。**

### REQ-24 「回顾」入口：日历与统计合并

- 参考产品：Day One 的 Timeline / On This Day 聚合、Apple 健康「摘要 / 浏览」二分
- 需求描述：将「日历」「统计」两个一级入口合并为一个，腾出的位置给 REQ-23。

**验收标准**
1. 一级入口由两项合并为一项，**标签不得沿用「日历」**——否则统计将彻底失去可发现性；建议命名「回顾」，图标沿用日历族
2. 入口内为「日历 / 统计」两个视图，**默认落在日历**：高频项不得为合并付出额外点击成本。窄屏（<900dp）以页首居中的分段控件切换；宽屏（≥900dp）左栏日历、右栏统计并排同屏，无需切换
3. 统计页现有内容（记录足迹卡片组、月报入口、心情趋势、最近 7 天、心情分布、标签排行）整体迁移，不做删减
4. 月报归属收敛到「回顾」内；首页引导卡（`home_page.dart:170`）保留为发现性入口，两处跳转到同一页面
5. 日历的选中日期与当前月份状态，在子页签切换、一级入口切换后保持不变
6. 合并后底部导航仍为 4 项，FAB「写手账」的位置与遮挡关系不变

**技术要点**：`CalendarPage` 与 `StatsPage` 均无自带 `AppBar`（前者返回 `SafeArea`，见 `calendar_page.dart:79`；后者返回 `ListView`，标题由页内 `_pageTitle` 绘制），合并成本显著低于 REQ-23。宿主页窄屏以页首分段控件（`SegmentedButton`）切换、宽屏左右并排（取代最初的 `AppBar(bottom: TabBar)`，避免与底部导航形成双层页签）后，`stats_page.dart:32` 的 `_pageTitle(context, '统计')` 应移除以免标题重复。`test/widget_test.dart:192`「导航到日历/统计/设置页」直接点击底栏 `Icons.insights_outlined`，需同步改为「先进回顾，再切统计子页签」。

## 三、P1 需求：清理

### REQ-25 设置页入口去重

- 需求描述：REQ-23 落地后，设置页「写作」段的模板与素材两行成为重复入口。重复入口不是冗余保险，而是让用户对「哪个才是正的」产生犹豫，同时把设置页继续往功能抽屉的方向推。

**验收标准**
1. 移除设置页「写作」段的「手账模板」（`settings_page.dart:135`）与「我的素材」（`settings_page.dart:157`）两行；该段仅保留写作提醒
2. **保留**「数据」段的素材包导入入口（`settings_page.dart:649`）——它是文件动作而非内容浏览，语义本就属于设置
3. 原两行携带的计数信息（内置 N 套 / 自建 N 套）若要保留，改为「数据」段的只读计数行，不带跳转箭头
4. 回归确认：删除后不存在任何因此失去可达性的路径

## 四、非功能需求（接续 NFR-08）

| 编号 | 需求 |
|---|---|
| NFR-09 | **导航状态保持**：一级入口之间切换不重建页面状态（滚动位置、选中日期、当前子页签、排序方式均保留）；切换底部导航不得触发 provider 全量重载 |
| NFR-10 | **深链一致性**：写作提醒通知（REQ-07，`app.dart:28`）、桌面小组件（REQ-14，`app.dart:30`）、素材包分享 / 打开文件（REQ-21，`main.dart:232`）三条外部入口在导航改版后行为完全不变，冷启动直达编辑器的逻辑不受影响 |
| NFR-11 | **双端与宽屏一致**：`NavigationRail`（≥700dp）与 `NavigationBar` 呈现相同的 4 个目的地与相同的子页签结构；Android 与 Windows 表现一致（延续 NFR-04） |
| NFR-12 | **测试同步**：导航结构变更需同步更新受影响的 Widget 测试，至少覆盖「4 个一级入口均可达」「回顾内两个子页签可达」「素材内两个子页签可达」「编辑器与导入回跳的整页形态仍可用」四条路径（延续 NFR-03） |

## 五、建议实施顺序

| 批次 | 内容 | 说明 |
|---|---|---|
| 第一批 | REQ-24 回顾合并 | 成本最低（两页均无自带 AppBar），先腾出一级入口的位置 |
| 第二批 | REQ-23 素材库入口 | 需先拆两个管理页的 Scaffold / AppBar / 多选态，本次主要工作量 |
| 第三批 | REQ-25 设置页去重 | 必须在 REQ-23 之后 |

**顺序不可颠倒**：REQ-25 若早于 REQ-23 执行，模板与素材会出现一段完全不可达的真空期。
