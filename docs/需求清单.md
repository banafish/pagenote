# 拾页 PageNote 功能增强需求清单

- 版本：v1.0（草案）
- 日期：2026-08-16
- 来源：竞品调研（Daylio、Day One、格志日记、flomo、时光手帐、Mori 手帐、念念手帐、丫丫手帐）
- 现状基线：v1.0.0+1，时间轴首页 + 日历补写 + 统计 + 心情/天气/标签/图片 + 搜索/收藏 + 深色模式/主题色

## 优先级定义

| 级别 | 含义 |
|---|---|
| P0 | 第一梯队：性价比最高，不动核心架构，数据复用现有字段 |
| P1 | 第二梯队：中等工程量，用户感知强，涉及新依赖或新表 |
| P2 | 第三梯队：大工程/差异化方向，按产品定位择机立项 |

---

## P0 需求

### REQ-01 那年今天（回忆）

- 参考产品：Day One "On This Day"、念念手帐"时光机"
- 需求描述：展示历史上同月同日写过の手账。

**验收标准**
1. 存在去年及以前同月同日的记录时，首页顶部展示「那年今天」卡片；无记录时不显示、不占位
2. 支持跨多年分组展示（如「2024 年的今天」「2023 年的今天」）
3. 点击卡片可进入条目查看/编辑
4. 当天补写的新条目不影响历史展示

**技术要点**：`JournalProvider` 内存数据按 `date` 的「月-日」过滤即可，无需改表。

### REQ-02 回收站（软删除）

- 参考产品：主流日记 app 通用做法
- 需求描述：删除不直接物理清除，先进回收站保留 30 天，期间可恢复。

**验收标准**
1. 全部删除入口（首页/日历/搜索）删除后进入回收站，并出现「撤销」即时提示
2. 提供回收站列表（设置页入口），支持单条恢复、单条彻底删除、一键清空
3. 回收站条目不计入首页时间轴、日历、统计、搜索结果
4. 超过 30 天的条目在启动时自动物理清除（连同附件图片文件）

**技术要点**：`entries` 表新增 `deletedAt INTEGER`（可空）；DB version 1→2 并补 `onUpgrade` 迁移机制（见 NFR-01）；所有查询加 `deletedAt IS NULL` 过滤；附件清理复用 `utils/attachments.dart`。

### REQ-03 数据导出与导入（备份）

- 参考产品：Daylio（CSV 导出）、flomo（JSON）
- 需求描述：设置页「数据」区提供完整备份（全部手账 + 附件图片打包）与恢复。

**验收标准**
1. 导出为单个 zip：内含 `entries.json`（全部字段）与 `attachments/` 图片目录；文件名含导出日期
2. 导入时校验格式，支持两种模式：合并（按 id 去重，`updatedAt` 新者胜）/ 覆盖（清空后导入）
3. 覆盖模式导入前二次确认并明确提示不可恢复
4. Android 与 Windows 双端可用（复用 `file_selector` 依赖）

**技术要点**：新增 `archive` 依赖打 zip 包；合并逻辑放 provider 层；导出在应用锁（REQ-08）开启时需先验证。

### REQ-04 每日一问（写作引导）

- 参考产品：格志日记（引导式提问）、Day One Prompt Library
- 需求描述：内置中文问题库，编辑页展示当日一问，解决「想写但不知道写什么」。

**验收标准**
1. 内置问题库 ≥100 条；每天按日期确定性展示一条（当天内不随重开变化）
2. 支持一键将问题插入正文开头；支持「换一条」（每日限 3 次）
3. 编辑历史条目时默认收起，可手动展开
4. 首页空状态页也展示今日一问，引导开始写作

**技术要点**：问题库为静态列表（如 `lib/data/prompts.dart`）；选取算法 `hash(日期) % 库长`。

### REQ-05 心情趋势折线图

- 参考产品：Daylio 情绪曲线
- 需求描述：统计页新增心情趋势折线，展现情绪随时间的变化。

**验收标准**
1. 心情枚举映射为 1–10 分值；一天多条取当日平均
2. 时间范围可切换：近 7 天 / 30 天 / 90 天
3. 无记录的日期断点或补空点处理明确，不产生误导
4. 展示区间平均分，并标记最高/最低点日期
5. 与现有自绘图表（AnimatedContainer 柱状/条形）风格统一，不引入图表库

**技术要点**：`stats_page.dart` 新增 CustomPainter 折线；纯内存计算。

### REQ-06 搜索筛选增强

- 参考产品：Day One Filters
- 需求描述：搜索页支持多维组合筛选。

**验收标准**
1. 筛选维度：心情（多选）、天气（多选）、标签（多选）、日期区间、只看收藏、只看有图
2. 筛选条件与关键词可任意组合，结果实时更新并展示命中数量
3. 已选条件以 chips 展示，支持单个移除与一键清空
4. 无关键词、仅用筛选条件也能检索

**技术要点**：仅 `search_page.dart` UI 层改动，基于内存数据过滤，不动数据库。

## P1 需求

### REQ-07 写作提醒通知

- 参考产品：Daylio、Day One
- 需求描述：每日固定时间本地通知提醒写手账。

**验收标准**
1. 设置页可开关提醒并选择时间（默认 21:30），通知文案从池中随机
2. Android 端处理通知权限申请；精确闹钟权限被拒时给出引导说明
3. 点击通知直达编辑页
4. Windows 端不支持时在设置页明确标注降级，不展示无效开关

**技术要点**：`flutter_local_notifications`（+ 时区处理）；入口 `settings_page.dart`。

### REQ-08 应用锁（隐私保护）

- 参考产品：Daylio（指纹 / Face ID）
- 需求描述：进入 app 需生物识别或 PIN 验证。

**验收标准**
1. 开启流程：设置 PIN（输入两次确认）→ 可选开启生物识别
2. 触发时机：冷启动，以及从后台返回超过设定时长（可选：立即 / 1 分钟 / 5 分钟）
3. PIN 连续错误 5 次锁定 30 秒
4. 无账号体系，忘记 PIN 无找回渠道：开启时明确告知风险并要求勾选确认；忘记即只能清除应用数据
5. 应用锁开启时，进入备份导出（REQ-03）需再次验证

**技术要点**：`local_auth`（Android 生物识别）+ PIN 加盐哈希存储；锁屏层挂 `app.dart` 根部。

### REQ-09 手账模板

- 参考产品：Day One Journal Templates
- 需求描述：内置常用模板，支持用户自建，新建手账可一键套用。

**验收标准**
1. 内置模板 ≥4 套：每日复盘 / 读书笔记 / 旅行手账 / 周记
2. 新建手账时可选模板，一键填充预设标题与分节结构
3. 任意手账可「另存为模板」；模板支持重命名、删除（内置模板不可删）
4. 模板随备份（REQ-03）一并导出/导入

**技术要点**：新表 `templates`（id/name/title/content/tags）或 SharedPreferences 存 JSON；编辑页加模板入口。

### REQ-10 周报 / 月报

- 参考产品：Daylio 周报月报
- 需求描述：自动生成月度写作报告。

**验收标准**
1. 报告内容：篇数、总字数、心情均值、高频标签 TOP5、最常记录的星期、对比上月增减
2. 统计页新增「月报」卡片，可切换查看历史月份
3. 每月首次打开 app 且上月有数据时，首页出现引导卡片「上月月报已生成」

**技术要点**：复用现有统计计算逻辑，纯 UI + 内存计算。

### REQ-11 导出长图 / 分享卡片

- 参考产品：时光手帐、Mori 手帐
- 需求描述：单篇手账一键渲染为精美长图，用于保存/分享。

**验收标准**
1. 条目卡片菜单提供「生成分享图」
2. 长图内容：日期、天气、心情、正文、图片（最多 3 张）、标签；延续纸质暖色风格；深色模式下导出仍用浅色模板
3. 底部 app 署名可在设置中关闭
4. Android 保存至相册并可拉起系统分享；Windows 保存为文件

**技术要点**：`RepaintBoundary` + `toImage` 渲染自绘卡片 Widget；`share_plus` / 相册保存插件。

### REQ-12 自定义活动打卡

- 参考产品：Daylio activities
- 需求描述：手账可附加当日活动标签（运动/阅读/聚餐等），并提供交叉统计。

**验收标准**
1. 编辑页心情/天气旁新增活动多选区；内置 ≥12 个预设图标，支持自定义活动名
2. 卡片与详情展示活动 icons；历史条目无活动数据时正常展示（字段可空）
3. 统计页新增「活动频率排行」与「做什么的时候心情最好」交叉统计

**技术要点**：`entries` 新增 `activities` 列（沿用 `\u001F` 分隔模式）；走 DB 迁移。

## P2 需求（择机立项）

### REQ-13 手账装饰排版（贴纸 / 胶带 / 背景）

- 参考产品：Mori 手帐、时光手帐、丫丫手帐
- 需求描述：先做轻量版：纸张背景（≥8 款程序绘制的纹理）+ emoji 贴纸（拖拽/缩放/旋转），导出长图包含装饰。
- 备注：完整画布版（自由图层、画笔、胶带）需将编辑器从文本流重构为元素树模型，建议轻量版验证需求后另立项。

### REQ-14 桌面小组件（Android）

- 参考产品：Daylio widget
- 需求描述：展示连续记录天数 + 今日是否已写 + 今日一问，点击直达编辑页。
- 技术要点：Glance Widget，仅 Android。

### REQ-15 WebDAV 自动备份 / 云同步

- 参考产品：Day One、Journey
- 需求描述：第一阶段做 WebDAV 定期单向备份（坚果云等），复用 REQ-03 打包格式；双向同步与冲突合并另评估。

### REQ-16 快速速记

- 参考产品：flomo
- 需求描述：不进完整编辑器的快速入口：一句话 + 可选图片直接入库，标记「未整理」，稍后可补充心情/标签整理成正式手账。

## 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-01 | 数据库迁移：引入 `onUpgrade` 机制，v1→v2 起全部走正式迁移路径，并补充迁移单元测试（当前 v1 无迁移逻辑） |
| NFR-02 | 性能：条目 ≥2000 条时首页滚动、搜索、统计保持流畅；验证全量内存加载方案，预留分页/索引优化空间 |
| NFR-03 | 测试：每个 P0 需求附带单元/Widget 测试，延续现有 `test/` 风格 |
| NFR-04 | 双端兼容：所有功能在 Android + Windows 可用，或在设置页明确降级提示（如通知、生物识别在 Windows 端） |
| NFR-05 | 隐私：不引入任何网络上报/统计 SDK；应用锁与备份导出联动验证 |

## 建议实施顺序

1. **第一批（P0）**：REQ-02 回收站（顺带落地 NFR-01 迁移机制）→ REQ-01 那年今天 → REQ-04 每日一问 → REQ-06 搜索筛选 → REQ-05 心情折线 → REQ-03 导出导入
2. **第二批（P1）**：REQ-07 提醒 → REQ-08 应用锁 → REQ-09 模板 → REQ-10 月报 → REQ-11 分享长图 → REQ-12 活动打卡
3. **第三批（P2）**：按产品方向二选一：偏记录习惯做 REQ-14/12 强化；偏手账美学做 REQ-13；REQ-15/16 视用户反馈排期
