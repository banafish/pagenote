## 一、背景与核心判断

### 现状盘点

| 维度 | 现状 | 位置 |
|---|---|---|
| 贴纸 | 32 个矢量自绘 + 30 个硬编码 emoji，4 分类 | `lib/models/sticker_assets.dart:26` |
| 胶带 | 6 纹样 × 6 色 | `lib/models/sticker_assets.dart:85` |
| 纸张 | 9 纹理 + 8 纯色 + 5 渐变 | `lib/models/decoration.dart:109` |
| 字体 | 3 款 OFL 中文字体 | `lib/models/app_fonts.dart:17` |
| 自定义素材 | **无**（调研报告第一阶段第 1 条「相册导入做贴纸」未落地） | — |
| 素材面板 | 3 页签平铺网格，点一次插入一个并立即关闭弹层，落点固定 (0.42, 0.46) | `lib/widgets/canvas/canvas_tool_sheets.dart:24` |
| 模板 | 6 套内置整页版式 + 用户「另存为模板」 | `lib/models/template.dart:76` |
| 模板管理 | 仅重命名 + 删除，**无缩略图、无复制、无导出** | `lib/pages/template_manager_page.dart` |
| 分享 / 导入 | 仅全量备份 zip（条目 + 模板 + 附件），无局部分享单位 | `lib/services/backup_service.dart:50` |

### 判断一：分发走「文件式」，不建服务端

竞品的素材管理分两条路线：

- **服务端路线**（时光手帐、念念、Canva、Notion）：素材中心 + 官方/博主供给 + 订阅变现。需要内容团队与服务器，与拾页「离线、免费、无账号、无网络上报（NFR-05）」的定位直接冲突。
- **文件式路线**（GoodNotes 模板、Procreate `.brushset`、Obsidian 主题、Figma 社区文件）：产品只定义格式，分发交给微信群 / 小红书 / QQ 群。零服务器成本，用户即内容供给方。

拾页只能走第二条，且有一项竞品无法复制的优势：**素材全部为程序绘制的矢量，一个模板包只有几 KB 的 JSON**。竞品的 PNG 素材包动辄数十 MB，必须走应用内下载；拾页的模板文件可以直接在微信群里传。原本作为成本妥协的「零图片资产」决策，在分发环节变成结构性优势。

### 判断二：分享包必须独立于备份 zip

| | 备份 zip（REQ-03） | 分享包（REQ-21） |
|---|---|---|
| 内容 | 自己的全量数据 | 别人的局部内容 |
| 信任级别 | 可信 | **不可信** |
| 动作语义 | 恢复（覆盖 / 按 updatedAt 合并） | 安装（追加、重新分配 id） |
| 冲突处理 | 新者胜 | 默认保留两者 |
| 典型体积 | 数 MB ～ 数十 MB | 数 KB ～ 数百 KB |

复用备份格式做分享，等于为了发一个模板给朋友寄整块硬盘，且会把「别人的数据」按「自己的数据」的信任级别写入本地。两者必须分开。

### 判断三：先补交互与缺陷，再做分享

素材面板与模板管理页的交互欠账不依赖任何格式设计，一两天见效；而 FIX-01～03 三个缺陷会让分享功能一上线就出错，属于强前置。顺序不能颠倒。

## 二、缺陷修复（P0，分享功能的强前置）

### FIX-01 模板内照片路径既不打包也不重映射

**现象**：从带照片的手账「另存为模板」后，模板跨设备必然碎图，且路径字符串会泄露本机用户名。

**成因链**：
1. `lib/providers/template_provider.dart:60` 的 `saveFromEntry` 直接 `canvas?.clone()`，把 `ImageElement.path` 的**本机绝对路径**原样存入模板；
2. `lib/services/backup_service.dart:60` 打包时只遍历 entries 的图片，**不含模板 canvas 内的图片**；
3. `lib/providers/journal_provider.dart:396` 的路径重映射只对 entries 生效，`importTemplates` 完全没有重映射逻辑。

**验收标准**
1. 「另存为模板」默认**清空所有 `ImageElement.path`，保留占位框**（与内置旅行模板 `lib/models/template.dart:243` 的 `path: ''` 一致）；模板本身的语义就是让使用者填自己的照片
2. 保存对话框提供「保留照片」勾选项（默认不勾）；勾选时照片必须一并进入备份包与分享包
3. 备份导入时对模板 canvas 的图片路径按文件名重映射，逻辑与 entries 一致
4. 补单测：另存含照片的条目为模板 → 导出 → 导入 → 模板可正常渲染，且不含任何绝对路径

**技术要点**：`saveFromEntry` 增加 `keepPhotos` 参数；`backup_service.buildZip` 的附件收集范围扩展到 `templates.*.canvas.images`；`importTemplates` 补 `remapImagePaths`。

### FIX-02 `builtin` 标志可被外部文件伪造，导入 id 语义错误

**现象**：手工改造的 zip 可以塞进永远删不掉的模板；他人分享的模板会按「同步」语义覆盖本地同 id 模板。

**成因**：
1. `lib/models/template.dart:65` 的 `fromMap` 直接读取 `builtin` 字段，而 `deleteTemplate` 对 `builtin == true` 直接 return；
2. `lib/providers/template_provider.dart:87` 的 `importTemplates` 按 id + `updatedAt` 新者胜——这是同步语义，对「别人的模板」是错的。

**验收标准**
1. 一切来自外部文件的模板，导入时强制 `builtin = false`
2. 分享包导入时**重新分配本地 id**，原 id 存入 `originId` 字段，用于后续识别「同一模板的新版本」
3. 备份导入（REQ-03）维持现有 id + `updatedAt` 语义不变，两条路径分离
4. 补单测：伪造 `builtin: 1` 的包导入后模板可正常删除

**技术要点**：`JournalTemplate` 增加可空 `originId`（走 DB 迁移，遵循 NFR-01）；导入分「恢复」与「安装」两个入口方法，不共用。

### FIX-03 未知素材 id 静默回退为星星

**现象**：`lib/models/sticker_assets.dart:147` 的 `_ => _star`。导入他人用新版本素材或自定义素材制作的模板时，缺失素材会静默变成一堆星星，用户只会觉得「这模板怎么这么丑」，无从排查。

**验收标准**
1. 分享包导入前校验引用完整性（贴纸 key、纸张 id、字体 family），缺失项在预览页明确列出：「3 个素材本机缺失，导入后显示为占位框」
2. 渲染端未知 key 显示**明确的缺失占位**（虚线框 + `?`），不再伪装成正常贴纸
3. 缺失占位可点击，提示缺失的素材名并允许替换为本机已有素材
4. 补单测：含未知 key 的 canvas 可正常解码、渲染不崩溃、且渲染结果与 `_star` 可区分

**技术要点**：`StickerPainter` 的 fallback 分支改为独立的 `_missing` 绘制函数；校验逻辑放 provider 层，供导入预览页复用。

## 三、P0 需求：交互补课

### REQ-17 素材面板交互升级

- 参考产品：Canva / Keynote（常驻抽屉连续插入）、时光手帐 / Telegram 贴纸面板（最近使用置顶）、微手帐（素材搜索）
- 需求描述：现有面板每插入一个素材就关闭，贴 6 个贴纸需要点 12 次；且所有素材落在同一坐标完全重叠；无最近使用、无收藏、无搜索。

**验收标准**
1. **最近使用**：面板首屏顶部一行横滑展示最近使用的 ≥12 个素材（贴纸 / 胶带 / emoji 混排），按最近使用时间倒序
2. **收藏**：素材长按可收藏 / 取消收藏；收藏区固定在最近使用之上，用户可手动排序
3. **常驻连续贴**：面板改为可折叠抽屉（折叠态约占屏幕下半部分，画布保持可见），点击素材插入画布后**面板不关闭**，可连续插入；抽屉提供明确的收起手势与按钮
4. **落点不重叠**：连续插入的素材依次做递增偏移（螺旋或对角偏移），任意两个新插入素材不得完全重合
5. **拖拽放置**：支持从抽屉长按拖拽素材到画布指定位置落下；点击则插入画布中心区域
6. **搜索**：面板顶部搜索框，按素材名与关键词匹配，跨三个页签统一检索
7. **emoji 页签**接入系统 emoji 全集并支持搜索，替换现有 30 个硬编码列表
8. 以上行为在 Android 与 Windows 双端一致（NFR-04）

**技术要点**：`StickerAsset` 增加 `keywords` 字段（每个素材 3～5 个中文关键词）；最近使用 / 收藏存 SharedPreferences（存 key 列表即可，无需入库）；`showStickerPalette` 由「返回单个元素并关闭」改为「回调式持续插入」，签名从 `Future<CanvasElement?>` 改为接受 `onPick` 回调；拖拽用 Flutter 原生 `Draggable` / `DragTarget`，落点坐标需按画布归一化系数换算。

### REQ-18 模板管理页升级

- 参考产品：GoodNotes（模板分组管理）、Notion（模板复制后编辑）、Day One Templates
- 需求描述：`lib/pages/template_manager_page.dart` 目前只有重命名与删除，连缩略图都没有——而 `lib/widgets/template_picker.dart:101` 里已有现成的 `CanvasView` 版式预览组件可直接复用。内置模板完全不可修改，用户想微调只能从零重做。

**验收标准**
1. 列表改为**网格 + 版式缩略图**，缩略图复用模板选择弹层的 `CanvasView` 渲染，所见即所得
2. 每个模板提供更多菜单：重命名 / **复制一份** / 导出分享（REQ-21 落地后启用）/ 删除
3. **内置模板支持「复制为我的模板」**，复制出的副本可自由改名、编辑、删除
4. 支持排序：按最近使用 / 按创建时间 / 手动拖拽置顶，选择项持久化
5. 空态引导文案：「把喜欢的一页另存为模板」，并提供跳转编辑器的入口
6. 模板数量 ≥30 时列表滚动流畅，缩略图懒渲染不卡顿（NFR-02）

**技术要点**：`JournalTemplate` 增加 `lastUsedAt` 与 `sortIndex`（走 DB 迁移，遵循 NFR-01）；复制内置模板即以 `newTemplateId()` 生成新 id 且 `builtin = false`；缩略图渲染建议加 `RepaintBoundary` 隔离。

## 四、P1 需求：素材扩容（分享包的前置）

### REQ-19 矢量贴纸换色

- 参考产品：时光手帐「变色贴纸」（其宣传卖点）
- 需求描述：胶带已支持 6 种配色（`lib/models/sticker_assets.dart:98`），但 32 个矢量贴纸的颜色全部硬编码在绘制函数里。矢量路线换色几乎零成本，而竞品的 PNG 素材做这件事非常困难——这是自绘路线独有的红利。

**验收标准**
1. 贴纸元素支持色调调整，每个贴纸提供 ≥6 种配色（复用 `stickerPaletteColors`）
2. 换色在素材面板选择时可选，插入画布后也可通过元素属性面板修改
3. 换色不破坏贴纸的多色层次（如小熊的鼻头、猫的胡须应保持可辨识），采用色相映射而非整体单色填充
4. 换色信息随 `StickerElement` 序列化，备份 / 分享 / 分享长图导出全链路一致
5. 存量数据无 tint 字段时按原配色渲染，不出现视觉突变

**技术要点**：`StickerElement` 增加 `tint` 字段（可空 int，空为原色）；`StickerPainter` 接收 tint 并对内部调色板做统一色相偏移（保留明度与饱和度关系）；32 个绘制函数无需逐个改写。

### REQ-20 自定义图片贴纸导入

- 参考产品：微手帐「素材导入 + 智能抠图」、念念手帐人像抠图
- 需求描述：调研报告第一阶段第 1 条原本就规划了「用户从相册导入图片做贴纸」，尚未落地。这是素材量的长尾解，**也是分享包的前提**——没有自定义素材这个实体，别人分享过来的素材就无处安放。

**验收标准**
1. 素材面板新增「我的」页签，支持从相册导入图片作为贴纸，导入后与内置贴纸同等使用（移动 / 缩放 / 旋转 / 图层）
2. 素材文件按内容哈希（sha1）存入应用目录 `stickers/`，同一图片重复导入自动去重
3. 支持带透明通道的 PNG 直接导入；对不透明图片提供「去白底」的基础处理
4. 自定义贴纸可重命名、分组、删除；删除时若被现有手账引用需二次确认，并说明引用处会显示缺失占位（FIX-03）
5. 单张素材尺寸与体积有上限（建议长边 ≤1024px、≤2MB），超限自动压缩并提示
6. 自定义贴纸随备份（REQ-03）导出 / 导入，路径按文件名重映射

**技术要点**：贴纸 key 扩展第三种前缀 `img:<sha1>`（现有为 `vec:` 与 `emoji:`，见 `lib/models/canvas_page.dart:207`）；内容寻址使 key 跨设备天然稳定，是分享包能正确引用素材的基础；抠图若做进阶方案，Android 端可评估 ML Kit Subject Segmentation（端上、免费、不触碰 NFR-05 的网络红线），Windows 端降级为手动橡皮。

## 五、P2 需求：分发机制

### REQ-21 素材 / 模板分享包

- 参考产品：GoodNotes 模板文件、Procreate `.brushset`、Telegram 贴纸包
- 需求描述：定义独立于备份的分享包格式，支持导出单个模板 / 素材集合并通过系统分享发出，以及导入他人的分享包。格式定义见本文档附录。

**验收标准**

*导出*
1. 模板管理页（REQ-18）单个模板可「导出分享」；也支持多选模板打包
2. 素材面板「我的」页签（REQ-20）可将自定义贴纸打包导出
3. 导出包内自动包含被引用的自定义素材文件，保证接收方开箱即用
4. 导出包内**不得包含任何本机绝对路径**（依赖 FIX-01）
5. 导出文件名含包名与日期；Android 拉起系统分享，Windows 走保存对话框（与 REQ-03 一致）

*导入*
6. 提供**导入预览页**：模板缩略图网格 + 「含 3 个模板 / 12 个贴纸 / 240 KB」+ 来源署名，用户勾选后才写入本地——不得沿用备份导入的「一个确认框全量导入」交互
7. 引用完整性校验结果在预览页明确展示（依赖 FIX-03）
8. 同名冲突默认「保留两者」（自动加后缀），可选覆盖；导入的模板一律新 id + `builtin = false`（依赖 FIX-02）
9. 导入完成后跳转到对应位置并高亮新增内容（模板 → 模板管理页；素材 → 素材面板「我的」）
10. 格式不符 / 损坏 / 版本过高时给出可读的中文错误，不崩溃（复用 `BackupFormatException` 的处理风格）

*平台集成*
11. Android 注册 `intent-filter`（`ACTION_VIEW` + `ACTION_SEND`，mime `application/zip`），在微信 / QQ 中点开文件可直接选择用拾页打开，进入导入预览页
12. Windows 端支持双击关联或从设置页手动选择文件导入

**技术要点**：复用现有 `archive` 依赖，零新增包；**扩展名就用 `.zip`**——国内实际分发渠道是微信 / QQ，自创扩展名（如 `.pnpack`）会导致「用其他应用打开」失效，类型判断放 `pack.json` 内部，与备份包用 `app: pagenote` 区分的思路一致；导入写盘前必须做路径消毒与体积限制（NFR-06）。

### REQ-22 官方精选包（可选）

- 参考产品：Obsidian 社区主题列表、Procreate 官方笔刷包
- 需求描述：维护一份官方精选包索引（GitHub Releases 或静态 JSON），用户在设置页手动点击「检查素材更新」时才联网拉取，平时完全离线。
- 备注：这是唯一会引入网络请求的功能，与 NFR-05「不引入任何网络上报 / 统计 SDK」的边界需明确——只允许用户主动触发的下载，不允许任何自动请求、不携带任何设备标识。若判断该边界不值得破，本需求可直接放弃，改由用户在社群自行流通分享包（REQ-21 已足够支撑）。

## 六、非功能需求（接续 NFR-05）

| 编号 | 需求 |
|---|---|
| NFR-06 | **不可信文件安全**：分享包解压前校验总解压体积与文件数上限（防解压炸弹）；写盘路径必须经消毒，拒绝 `..` 与绝对路径条目（防路径穿越）；图片解码前校验尺寸上限；单个包体积上限建议 20MB |
| NFR-07 | **格式版本兼容**：`pack.json` 带 `format` 版本号；遇到高于当前支持版本的包，明确提示「该素材包需要更新版本的拾页」，不做部分导入；低版本包必须能被高版本正确读取 |
| NFR-08 | **素材 id 稳定性**：内置素材 id（`vec:` / 纸张 / 字体 family）一经发布不得重命名或删除，只能新增——否则历史模板与已分发的分享包会大面积失效。删除素材需走 FIX-03 的缺失占位路径 |

## 七、建议实施顺序

## 附录：分享包格式定义（草案）

```
拾页素材包-<包名>-<日期>.zip
├── pack.json            # 包元信息
├── templates.json       # [JournalTemplate.toMap()]，canvas 内以 key 引用素材
├── stickers.json        # [{id, name, category, keywords}]，自定义贴纸清单
├── assets/
│   └── <sha1>.png       # 自定义贴纸位图（内容寻址，与 REQ-20 的存储一致）
└── cover.png            # 列表预览图（可选）
```

`pack.json` 结构：

```json
{
  "app": "pagenote",
  "format": 1,
  "kind": "template",
  "id": "pack-xxxx",
  "name": "秋日旅行模板集",
  "author": "用户填写，可留空",
  "version": 1,
  "createdAt": "2026-08-18T10:00:00.000",
  "counts": { "templates": 3, "stickers": 12 }
}
```

设计约束：

1. `kind` 取 `template` / `sticker` / `mixed`，与备份包通过 `app` + 顶层结构区分（备份包顶层是 `entries` / `templates`，分享包顶层是 `pack.json`）
2. `templates.json` 中的 canvas 只允许通过 key 引用素材（`vec:` / `emoji:` / `img:<sha1>`），**不得出现任何本机文件路径**
3. `img:<sha1>` 引用的文件必须存在于 `assets/`，否则该素材在导入预览页标记为缺失
4. 导入时 `id` 落为本地模板的 `originId`，本地重新分配 id（FIX-02）
5. 未来新增字段一律可选，老版本读到未知字段直接忽略（NFR-07）
