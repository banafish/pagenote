## 一、背景与核心判断

### 现状盘点

| 维度 | 现状 | 位置 |
|---|---|---|
| 素材页结构 | 「模板 / 贴纸」两个子页签（REQ-23） | `lib/pages/library_page.dart` |
| 模板 tab | 纯平铺网格，带 `packId` 的模板不可区分 | `lib/pages/template_manager_page.dart` |
| 贴纸 tab | 每包一节（包头：名称 + n 贴纸 · n 模板 + ⋯ 菜单）+ 未分组按 category 分节 | `lib/pages/sticker_manager_page.dart:450` |

| 导入回跳 | 连续 push 模板管理页、贴纸管理页各一次，分别高亮 | `lib/main.dart:236-251`、`lib/pages/settings_page.dart:643-659` |

### 判断一：数据模型已经包优先，UI 还没跟上

v8 落地后，一个包可以同时装贴纸和模板，贴纸页的包头也已经会显示「n 张贴纸 · n 套模板」——但整个应用里**没有任何地方能按包浏览模板**：模板 tab 平铺，`packId` 不可见。用户导入「秋日旅行包 · 8 个模板」，这 8 个模板从此散落在平铺列表里，包的边界只在贴纸页的 section 头上残存一半。包详情页是让 v8 投资兑现的地方。

### 判断二：包是一等分享单位，需要一等导航对象

分享包按 `originId` 去重、同一转发链收敛到同一个本地包——「一个包 = 一次导入 = 一个收藏集」是既成的心智模型。导入完成后的回跳要连续 push 两个管理页分别高亮，正是包没有自己的页面的症状。包有了详情页，回跳就有了天然落点。

### 判断三：包优先 ≠ 只有包

不是所有内容都在包里：内置模板被设计为永不入包，自建模板与散装贴纸的 `packId` 为 null。若首页语义上就是「包列表」，新用户（没有包）点开素材一级入口只会看到空列表——这违背 REQ-23.2 特意论证过的「首屏永不为空」。因此首页必须置顶**内容型入口**（背后永远有实际内容的固定入口）：内置模板恒非空，未分组对没导过包的用户就是全部家当。同时，整理的收益必须在取用时兑现（REQ-28），否则包概念只在管理页成立，用户感知割裂。

```
素材
┌──────────────────────────────┐
│ ▣ 内置模板              6 套 › │  ← 置顶固定入口，永远非空
│ ▣ 未分组      12 贴纸 · 3 模板 › │  ← 置顶固定入口（散装贴纸 + 自建模板）
├──────────────────────────────┤
│ 我的素材包                      │
│ ┌────────┐  ┌────────┐       │
│ │ [封面]  │  │ [封面]  │       │  ← 包卡片：封面 / 占位、包名、
│ │秋日旅行  │  │ 胶带集  │       │     计数、作者署名，长按拖拽排序
│ │12贴·3模 │  │ 8 贴   │       │
│ └────────┘  └────────┘       │
└──────────────────────────────┘
```

## 二、P0 需求

### REQ-26 素材页「包列表 → 包详情」重构

- 参考产品：Telegram 贴纸包管理、Procreate 画笔库、GoodNotes 模板分组
- 需求描述：素材一级入口从「模板 / 贴纸两个子页签」改为**包列表首页**：置顶「内置模板」「未分组」两个固定内容入口，下方为用户的素材包列表；点卡片进入包详情页，同屏浏览包内贴纸与模板。本需求修订 REQ-23 的子页签结构（一级入口置换本身不变）。

**验收标准**

1. **首页结构**：置顶「内置模板」「未分组」两个固定内容入口 + 「我的素材包」区（包卡片：封面或占位、包名、n 贴纸 · n 模板、作者署名）；内置模板入口永远存在，首屏永不为空（延续 REQ-23.2 的意图）
2. **固定入口与包详情同构**：三处使用同一个详情页组件、不同数据源——内置模板 = builtin 模板网格（只读 + 复制为我的模板，现状行为）；未分组 = `packId` 为 null 的贴纸（保留 category 分节）+ 自建模板（**继承现有「最近使用 / 创建时间 / 手动排序」三档排序与长按拖排**，`template_manager_page.dart:411-451` 的能力整体迁移至此）；包详情 = 指定包的贴纸网格 + 模板网格
3. **包详情页动作**：包级操作上移到详情页——重命名 / 上传封面（REQ-27）/ 整包导出 / 解散 / 删除（沿用现有删除语义与引用检查弹窗）；贴纸单项菜单（重命名 / 移动到素材包 / 分组 / 导出 / 删除）与现状一致
4. **导入回跳直达包详情**：分享包导入完成后 push 对应包详情页并高亮新内容（`highlightIds` / `highlightStickerIds`），替换现在连续 push 两个管理页的方案（`main.dart:236-251`、`settings_page.dart:643-659`）
5. **包手动排序**：包列表支持长按拖拽排序并持久化；存量包以现有 `createdAt` 倒序作为初始顺序，新建 / 新导入的包默认排最前
6. **新建空包**：「我的素材包」区提供「新建素材包」入口（命名后直接进入空包详情页）——解决现在空包只能通过「移动贴纸到包」间接创建的问题
7. **多选导出**：各详情页内多选导出为素材包，交互沿用现状（多选态替换顶栏 + 全选 + 导出）；包详情内可同时勾选贴纸与模板（设置页 `_SharePackExportPage` 已有混选先例）。列表页**不做**跨包多选——跨包分发用「逐包整包导出」替代，这是对现有贴纸 tab 跨 section 多选能力的有意取舍
8. **空态**：无任何包时「我的素材包」区显示引导（导入素材包指路设置页——延续 REQ-25.2「文件动作属于设置」的划分；引导把散装贴纸挪进包），固定入口不受影响
9. **整页形态**：素材首页与包详情页均为可独立 push 的路由——编辑器贴纸面板「管理我的素材」（`canvas_tool_sheets.dart:833-841`）改为 push 素材首页；`TemplateManagerPage` / `StickerManagerPage` 的独立整页壳退役，其 body 组件被详情页复用，不保留双份维护（修订 REQ-23.5 的载体，可达性要求不变）
10. **宽屏一致**：`NavigationRail`（≥700dp）下结构与窄屏一致（延续 NFR-11）

**技术要点**：`library_page.dart` 宿主重写（移除 TabBar / IndexedStack 与跨页签多选上提，多选态下沉到详情页）；详情页组件三份数据源（builtin 过滤 / `packId == null` / 指定包 id），provider 层现有 `packs` / `stickersOfPack` / `templatesOfPack` / `ungroupedStickers` 已够用；`SharePackImportResult` 需带回落地的包 id 供回跳使用；DB v9 迁移（与 REQ-27 共用一次）：`sticker_packs` 表 `ADD COLUMN sortIndex INTEGER NOT NULL DEFAULT 0`、`ADD COLUMN coverPath TEXT`，`StickerPack` 模型同步扩展 `toMap` / `fromMap`；受影响的 Widget 测试路径同步更新（延续 NFR-12）。

### REQ-27 包封面（用户上传，不自动合成）

- 参考产品：Telegram 贴纸包封面、微信表情专辑封面
- 需求描述：包封面由用户自己上传图片，**不做从包内容自动合成**；分享包内 `cover.png` 作为导入时的初始封面。激活分享包格式附录中一直未实现的可选字段。

**验收标准**

1. `StickerPack` 新增 `coverPath`（可空；DB v9 迁移，见 REQ-26 技术要点），未设置时包卡片显示统一占位（主色底 + 图标 / 包名首字），**不得**用包内贴纸自动拼合
2. **上传入口**：包详情页的包信息区提供「上传封面 / 更换封面 / 移除封面」，从相册选图
3. **存储**：封面文件按内容 sha1 存入应用目录独立子目录（建议 `pack_covers/`，与贴纸的 `stickers/` 分开，避免污染自定义贴纸索引），DB 只存相对文件名
4. **尺寸限制**：长边 ≤1024px、单文件 ≤2MB，超限自动压缩并提示（对齐 REQ-20.5 的贴纸约束）
5. **分享包导入**：包内 `cover.png` 自动存为本机封面（`SharePackService` 目前未读取该文件，需补齐解析）；解码前做尺寸上限校验——封面来自不可信文件，约束与 NFR-06 一致
6. **分享包导出**：整包导出时若有封面则写入 `cover.png`；格式不升版（该字段在附录中本就可选，老版本按 NFR-07 忽略未知条目，不受影响）
7. **备份**：封面文件随备份导出（`pack_covers/` 目录与 `sticker_packs.json` 清单），恢复时按文件名重映射（对齐 REQ-20.6 的贴纸路径重映射）
8. **清理**：删除包、解散包时同步清理封面文件

**技术要点**：相册选图与压缩复用 REQ-20 的图片处理链（不做去白底）；`backup_service.dart` 目前导出 `stickers/` + `sticker_packs.json`，封面走同级新增目录；`share_pack_service.dart` 导入端补 `cover.png` → 存文件 → 写 `coverPath`，导出端补 `coverPath` → `cover.png`。

### REQ-28 模板选择弹层按包分节（取用侧对齐）

- 参考产品：编辑器贴纸面板「我的」tab 的包筛选 chips（应用内既有模式）
- 需求描述：模板选择弹层（`showTemplatePicker`）把全部模板一股脑平铺，包结构在**取用的那一刻**不可见——用户在素材页按包整理好，写作选模板时仍是一锅粥。改为按「内置模板 / 未分组 / 各包」分节，与包优先的管理侧同批上线。

**验收标准**

1. 弹层列表分节：内置模板置顶 → 未分组（自建）→ 各包（顺序与素材页包列表一致，即 REQ-26.5 的手动排序），每节带节头（节名 + 数量）
2. 节内顺序沿用 provider 现有排序；tile 渲染、预览与套用返回逻辑完全不变
3. 空节不显示；分节后 tile 上的「内置」badge 保留
4. 双端行为一致（NFR-04）
5. **与 REQ-26 同版本上线**：包概念在管理与取用两侧同时成立，不允许只改管理侧

**技术要点**：`template_picker.dart:40-45` 的平铺 for 循环改为按 `builtin` / `packId` 分组后分节渲染；包顺序读 `CustomStickerProvider.packs` 的 `sortIndex`；节头样式与素材页包头统一；弹层高度与滚动行为不变。
